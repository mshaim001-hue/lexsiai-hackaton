# Задача 5.3. Проверить расчёт GRPO loss по фактическому контексту каждого хода. Стоп до backward.

Возьми сохранённый успешный t0 / seed 100 из задачи 5.2. Для каждого хода собери пару: точные input_ids из model.generate и токены, которые модель сгенерировала на этом ходе. Используй исходные token IDs, без повторной токенизации текста. Сделай минимальный forward, который считает logprob только сгенерированных токенов. Наблюдения инструментов должны быть доступны модели как контекст и исключены из loss.

Покажи по каждому ходу, что префикс при scoring побайтно совпадает с префиксом генерации. Сверь logprob выбранных токенов с эталонным forward той же модели в eval-режиме. Укажи допуск и максимальное расхождение. Если сохранённых token IDs недостаточно, повтори только один rollout t0 / seed 100 с нужным логированием.

Проверь на scripted-группе m0, что награда и advantage вычисляются один раз на траекторию в исходной группе из четырёх rollout. Токены каждого хода получают advantage своей траектории. Покажи, как агрегируется loss и как длина ответа и число ходов влияют на вес эпизода.

Верни diff, команду проверки, таблицу совпадения префиксов и logprob, схему агрегации и `optimizer_steps=0`. Если текущий TRL требует одну плоскую последовательность на эпизод, укажи точное место и предложи минимальную точку расширения. На этом этапе достаточно проверяемого прототипа.
